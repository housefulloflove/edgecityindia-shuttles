Edge City India Shuttles

A live shuttle tracker for the Riva ↔ Circle shuttles at Edge City India 2026 in Mandrem, Goa (11 Oct – 1 Nov 2026). Attendees picked their stop and saw where the shuttle was and when it would reach them.

The event has ended The code stays here for anyone running shuttles at their own event.

How it was used

Attendees

A public page asks “Where are you?” and answers “Here in N min” or “here now”, with the day’s schedule. A Telegram bot sends arrival alerts and notices for your stop. The public side never shows lateness: it says where the shuttle is, calmly.

Drivers

One phone per vehicle shares its location. Android phones ran the driver app, paired by QR or 6-digit code. iPhones shared Telegram live location with the bot after /pair, with the Traccar Client app as a backup.

Ops team

A phone-first admin site (live board with map, phones, vehicles, schedule, notices, insights, activity), Telegram alerts with action buttons, and an MCP server so an AI agent could read state and propose changes for a person to confirm.

Architecture

A pnpm monorepo. One Docker image runs twice: as the web app and, with ROLE=worker, as the worker. Postgres holds everything. The server decides when phones track: each phone syncs, gets its desired mode back (active, idle, killed, revoked) and reconciles.

What’s in the repo

apps/webNext.js site: public page with map, phone-first admin, Telegram bot webhook, device endpoints, and the MCP server (/api/mcp, OAuth). Holds the single service layer and the database schema.
apps/workerScheduled jobs (croner): watchdog for silent or off-route phones, service windows, arrival alerts, notices, a Telegram and push queue, nightly learning of leg and dwell times, cleanup. Postgres locks prevent double sends.
apps/driverExpo (Android) app: pairing by QR or code, permission checklist, GPS while active (about every 10 s), check-ins while idle, offline queue, server-controlled over-the-air updates.
packages/sharedContracts, schedule maths and IST time helpers, shared by all three apps.

Every write goes through one service layer: one transaction and one audit-log row per change. Admin pages, API routes, the bot webhook, MCP tools and worker jobs are thin adapters around it. Over MCP, changes are proposed first and applied only after a person confirms.

Run it locally

You need Node 22+, pnpm and Docker (for Postgres).

pnpm install
docker compose -f docker-compose.dev.yml up -d     # Postgres on 127.0.0.1:5548
cp apps/web/.env.example apps/web/.env.local       # fill in SESSION_SECRET and TOKEN_SECRETS (random strings)
pnpm dev                                           # web + worker

Telegram is optional: leave TELEGRAM_BOT_TOKEN empty and the bot stays off. To watch fake shuttles drive the route, try pnpm sim. Tests:

pnpm test-db        # throwaway Postgres for tests (port 5547)
pnpm test           # unit + database tests
pnpm typecheck && pnpm lint

Self-host it for your event

Stops, routes, services, vehicles and staffing are data, not code: set them up in the admin site (or over MCP), then pair a phone per vehicle. For production, build the root Dockerfile and run it twice, once as web (default) and once with ROLE=worker, against your own Postgres. Web applies database migrations on start. apps/web/.env.example lists every variable.

You’ll also need your own Telegram bot (via @BotFather) and, for the Android driver app, your own Expo and Firebase projects (replace apps/driver/google-services.json, eas.json and the package id in app.config.ts). Stop names, copy and art are Edge City India’s; swap them freely.
